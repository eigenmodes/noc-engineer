הגדרות שאומתו מול Hermes v0.22.5 מסומנות ✔. מה שמסומן **לבדוק** לא נבדק על המערכת שלכם.

## 2. מהירות שמורגשת

### 2.1 אישור מיידי
כלל ל-`SOUL.md`:
```markdown
- Before any tool call in chat, reply with one short line that says what you are checking
  (object + window), in the user's language. Example: "בודק את srv1, הרמטיות בשעתיים האחרונות…".
  Do not repeat it later.
```
בגלל החשיבה, גם השורה הזאת עוברת סבב אחד מול המודל. הודעה מערכתית מיידית מגיעה מ-`long_running_notifications` (סעיף 2.2).

### 2.2 תצוגה ב-Mattermost ✔
```yaml
streaming:
  enabled: true                      # Mattermost תומך בעריכת הודעות: הטקסט מופיע תוך כדי כתיבה
display:
  platforms:
    mattermost:
      tool_progress: 'off'           # בלי הודעות על כלים ונתיבים
      interim_assistant_messages: false
      long_running_notifications: true   # הודעה אחת "עובד על זה" כשהשקט ארוך
      live_status: verb              # רק הפעולה, בלי ארגומנטים
```

### 2.3 פחות סבבים
עד 3 סבבים לשאלה, בעזרת פקודת חקירה מרוכזת (`PERFORMANCE.md` סעיף 3.1). זה ההבדל בין 30 שניות לשלוש דקות, יותר מכל הגדרת תצוגה.

## 3. תבניות תשובה
מכניסים אותן ל-`SOUL.md` (המבנה הכללי) ול-skills (התבנית של כל סוג תשובה). כללים לכל התבניות:
- **אורך:** מסך אחד. פירוט רק כשמבקשים ("תרחיב").
- **שפה:** כמו של הפונה. מונחים טכניים כמו hop, rule ושמות שרתים נשארים כמו שהם.
- **מספרים:** תמיד עם בסיס השוואה ("ירידה של 59% מול אותה שעה בשבוע שעבר") ועם שעה.
- **סטטוס** קטגוריאלי (`CONFIRMED` / `HIGH_CONFIDENCE` / `INCONCLUSIVE` / `INVESTIGATION_INCOMPLETE`), לא אחוזים.
- **ראיות בסוף,** קצרות: שאילתה, חלון זמן וערך.
- אמוג'י אחד לחומרה בתחילת השורה הראשונה, ולא יותר: 🔴 תקלה, 🟠 חשד, 🟢 תקין, ⚪ לא חד-משמעי.

### 3.1 חקירה (צוות)
```
🔴 הבעיה ב-enrichment, לא בשרת. התחילה ב-13:42.
סטטוס: HIGH_CONFIDENCE

• איפה: enrichment, ירידה של 59% מול שבוע שעבר. ingress ו-capture תקינים
• למה: עדכון קונפיגורציה #881 ב-13:40, ו-312 שגיאות timeout ל-<service> אחריו
• מה עכשיו: לבדוק את #881 מול צוות ה-rules

ראיות:
• rule_rate{server="srv1"} 13:00–15:00: 0.41 מול 7d
• ECK <index>: "timeout" אחרי 13:42, 312 מופעים
לא נבדק: Argo (אין גישה)
```

### 3.2 תשובה ללקוח
```
זיהינו ירידה בהתאמות בשרת שלכם srv1, החל מ-13:42.
הסיבה בבדיקה מול הצוות הרלוונטי, ועדכון יישלח בטיקט <JIRA-123>.
בשלב זה אין צורך בפעולה מצדכם.
```
בלי שמות של hops פנימיים, בלי שאילתות, ובלי מידע על לקוחות אחרים (`SECURITY.md` שורה 5).

### 3.3 אנומליה מה-cron
```
🟠 [INV-0412] port_in_rate ירד ב-srv7: 0.38 מול שבוע שעבר (מ-10:35)
עוד 2 ממצאים: srv8, srv9 (אותו דפוס) · שאלו "@bot תסביר את INV-0412"
```
שורה אחת לכל ממצא. מזהה כדי שאפשר יהיה לשאול עליו. הודעה רק על ממצא חדש (`../WAKE-AGENT.md`).

### 3.4 סיכום בוקר (09:00)
```
☀️ סיכום 24 שעות · 3 ממצאים חדשים · 1 עדיין פתוח
• 🔴 srv7 port_in ירידה מ-10:35, פתוח (INV-0412)
• 🟢 rule 4711 חזר לשגרה ב-16:20 (INV-0398)
• 🟠 Kafka lag עלה בלילה, נורמלי מ-05:10
סריקות: 288/288 הצליחו
```
5–8 שורות. מה שעדיין פתוח מופיע ראשון.

### 3.5 כשמשהו לא זמין
```
⚪ לא הצלחתי לבדוק עד הסוף: ECK לא זמין (timeout).
מה כן בדקתי: Prometheus (תעבורה ו-rule rate תקינים מול שבוע שעבר), Jira (אין טיקטים פתוחים על srv1).
אנסה שוב אם תשאלו בעוד כמה דקות.
```
לעולם לא שקט, ולעולם לא "לא יודע" בלי לפרט מה נבדק.

## 4. התנהגות של מהנדס
כללים ל-`SOUL.md`:
```markdown
- Ask at most one question, only when a required fact is missing (which server, which time). Otherwise act.
- Never answer "I don't know" without checking. Say what you checked and what you could not.
- Never state a value no tool returned.
- If a question is outside the NOC domain, say so in one line and who handles it.
- When asked about a message you posted, find it (cron/output, INV id) and quote it before explaining.
```

**לבדוק:** שהמודל רואה מי כותב לו. בלי זה אי אפשר להתאים את הסגנון לקהל ולא לבודד לקוחות.

## 6. הודעות אוטומטיות בלי הצפה
- **אנומליות:** רק ממצא חדש, שורה אחת, ומקובצות באותה הודעה.
- **שגיאות backend:** פעם בשעה לכל שגיאה (`../WAKE-AGENT.md`).
- **`cron.wrap_response: false`** ✔: בלי כותרת ושורת סיום מסביב לכל הודעת cron.
- **סיכום הבוקר:** מה פתוח, מה נסגר, ושורה אחת על תקינות הסריקות.
